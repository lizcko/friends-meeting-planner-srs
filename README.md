
# Планировщик встреч с друзьями

## О проекте

«Планировщик встреч с друзьями» — учебное веб-приложение для организации совместных встреч, управления списком участников и выбора удобной даты и времени путём голосования.

Проект разработан в рамках лабораторных работ по разработке программного обеспечения, управлению требованиями, планированию и контролю версий.

## Цель проекта

Создать удобный инструмент, позволяющий организатору предложить встречу, добавить участников, определить возможные даты и выбрать наиболее подходящий вариант на основе результатов голосования.

## Реализованные возможности

- Создание встречи с названием, описанием и местом проведения.
- Отображение списка созданных встреч.
- Добавление участников к встрече.
- Удаление участников.
- Проверка повторного добавления участника.
- Добавление нескольких вариантов даты и времени.
- Проверка повторяющихся вариантов.
- Выбор участника для голосования.
- Голосование за один или несколько вариантов.
- Изменение ранее сохранённого голоса.
- Автоматический подсчёт голосов.
- Выделение вариантов с наибольшим количеством голосов.
- Сохранение данных в localStorage.
- Адаптивный интерфейс.

## Лабораторная работа № 4. Проектирование базы данных

Для приложения «Планировщик встреч с друзьями» спроектирована реляционная база данных SQLite.

Модель предназначена для хранения пользователей, встреч, участников, вариантов даты и времени, а также голосов.

### Основные таблицы

| Таблица | Назначение |
|---|---|
| `Users` | Данные пользователей и их учётные сведения. |
| `Meetings` | Встречи: название, описание, место проведения и создатель. |
| `Participants` | Связь пользователей со встречами, в которых они участвуют. |
| `DateOptions` | Варианты даты и времени; `is_final` указывает итоговый вариант. |
| `Votes` | Голоса участников за варианты даты и времени. |

Между таблицами предусмотрены шесть связей типа «один ко многим» (1:N).

Для поддержания целостности используются первичные и внешние ключи, ограничения `NOT NULL`, `UNIQUE`, `CHECK`, индексы и триггеры.

Дополнительные проверки предотвращают:

- Дублирование участников одной встречи.
- Повторение одинаковых вариантов даты и времени.
- Выбор более одного итогового варианта для одной встречи.
- Голосование за варианты даты, относящиеся к другой встрече.

### Нормализация до 3НФ

Структура базы данных приведена к третьей нормальной форме (3НФ).

Таблицы разделены по сущностям, чтобы уменьшить избыточность данных и избежать аномалий обновления.

Выполнено обоснование соответствия:

- Первой нормальной форме (1НФ).
- Второй нормальной форме (2НФ).
- Третьей нормальной форме (3НФ).

Подробное описание:

[Документация нормализации](database/normalization.md)

### Создание и проверка базы данных

Для проверки используется SQLite.

Порядок выполнения:

1. Создать новую пустую базу данных SQLite.
2. Выполнить `database/schema.sql`.
3. Выполнить `database/seed_data.sql`.
4. Проверить созданные таблицы.
5. Проверить корректность тестовых данных.
6. Проверить ограничения целостности.
7. Выполнить `PRAGMA foreign_key_check;`.

Пример команд для SQLite CLI:

```bash
sqlite3 meetings.db ".read database/schema.sql"
sqlite3 meetings.db ".read database/seed_data.sql"
sqlite3 meetings.db "PRAGMA foreign_key_check;"
```

Если нарушений внешних ключей нет, команда `PRAGMA foreign_key_check;` не выводит строк.

Тестовый набор содержит:

- 3 пользователя.
- 2 встречи.
- 5 участников.
- 4 варианта даты и времени.
- 7 голосов.

- Созданы SQL-скрипты.

- Реализованы ограничения целостности.
- Добавлены индексы.
- Подготовлена документация.
- Изменения оформлены с использованием Git и GitHub.

**Важно:** база данных создана как самостоятельный учебный результат лабораторной работы № 4.

Действующий веб-прототип сохраняет данные в `localStorage` и пока не подключён к SQLite.

Поле `is_final` в базе данных предусмотрено для хранения итоговой даты, однако функция утверждения даты ещё не реализована в интерфейсе приложения.

## Запуск приложения

Приложение не требует установки дополнительных библиотек или сервера.

### Способ 1. GitHub Pages

Открыть опубликованное приложение:

https://lizcko.github.io/friends-meeting-planner-srs/

### Способ 2. Локальный запуск

1. Скачать репозиторий с GitHub.
2. Распаковать архив на компьютер.
3. Открыть файл `index.html` в современном браузере.
4. Начать создание встреч.

Для корректной работы рекомендуется использовать актуальную версию Google Chrome, Microsoft Edge или Firefox.

## Инструкция пользователя

1. Заполнить название, описание и место встречи.
2. Нажать «Создать встречу».
3. Добавить участников.
4. Предложить несколько вариантов даты и времени.
5. Выбрать участника в разделе «Голосование».
6. Отметить подходящие варианты.
7. Нажать «Сохранить голос».
8. Просмотреть результаты голосования.

Данные сохраняются в браузере и доступны после обновления страницы.

## Автоматическая проверка качества

В проекте настроен GitHub Actions.

Файл конфигурации:

`.github/workflows/ci.yml`

При изменениях в основной ветке выполняются:

1. Проверка наличия основных файлов.
2. Проверка синтаксиса JavaScript.
3. Проверка наличия ключевых функций приложения.

Также предусмотрен запуск проверок при создании Pull Request в ветку `main`.

Автоматические проверки не заменяют функциональное тестирование веб-приложения и отдельную проверку SQL-скриптов.

## Ограничения текущей версии

Приложение представляет собой учебный прототип.

- Данные сохраняются только в браузере пользователя.
- Серверная база данных отсутствует.
- Синхронизация между разными устройствами не реализована.
- Авторизация пользователей отсутствует.
- Выбор участника в списке не является подтверждением личности.
- Итоговая дата встречи автоматически не утверждается в приложении.
- Автоматические проверки не заменяют полноценное функциональное тестирование.
